## 🛠️ Code Generation Standards

When writing code for this project, ALWAYS:

### **1. Layer Separation**

- **Repository**: Only data access, no business logic
- **Service**: Business logic, validation, transformation
- **Controller**: Request validation, response formatting
- **Router**: Endpoint definition, middleware application

### **2. TypeScript Best Practices**

```typescript
// ✅ Always define types
interface Employee {
  manv: string;
  hoten: string;
  chucvu: string;
  luong: number;
}

// ✅ Use strong typing
const calculateSalary = (employee: Employee): number => {
  return employee.luong * 1.1;
};

// ✅ Avoid 'any' type
// ❌ DON'T: const data: any = result;
// ✅ DO: const data: Employee[] = result;
```

### **3. Error Handling**

```typescript
try {
  const data = await repository.getData();
  if (!data) throw new Error("Data not found");
  return data;
} catch (error) {
  throw new Error(`Service error: ${error.message}`);
}
```

### **4. Validation in Service Layer**

```typescript
// Always validate before persistence
if (!data.manv || data.manv.trim().length === 0) {
  throw new Error("Employee ID is required");
}

if (data.luong < 0) {
  throw new Error("Salary must be positive");
}

// Check business rules
const existing = await repository.getByMaNV(data.manv);
if (existing) {
  throw new Error("Employee ID already exists");
}
```

### **5. Parameterized SQL Queries**

```typescript
// ✅ CORRECT - Prevents SQL injection
const result = await appPool
  .request()
  .input("MaNV", sql.VarChar, manv)
  .query("SELECT * FROM NHAN_VIEN WHERE MANV = @MaNV");

// ❌ WRONG - SQL injection vulnerability
const result = await appPool
  .request()
  .query(`SELECT * FROM NHAN_VIEN WHERE MANV = '${manv}'`);
```

## 📝 Naming & File Conventions

### **TypeScript File Naming**

- `<domain>Service.ts` - Business logic
- `<domain>Controller.ts` - HTTP handlers
- `<domain>Repository.ts` - Data access
- `<domain>Routes.ts` - Endpoint definitions
- `<domain>.ts` in `types/` - Type definitions

### **Code Naming**

- **Functions/Variables**: `camelCase` - `getEmployee()`, `employeeData`
- **Classes/Interfaces**: `PascalCase` - `EmployeeService`, `IEmployee`
- **Constants**: `UPPER_SNAKE_CASE` - `DEFAULT_PAGE_SIZE`, `JWT_EXPIRY`
- **Database Objects**: Vietnamese, PascalCase - `NHAN_VIEN`, `PHONG_BAN`
- **Stored Procedures**: `sp_<action><entity>` - `sp_createEmployee`, `sp_getPayrollByMonth`

## 🔐 Security Practices

When writing authentication/authorization code:

1. **Never store plain passwords** - Always use bcryptjs
2. **Parameterize all queries** - Prevent SQL injection
3. **Validate all inputs** - Check types, lengths, formats
4. **Use JWT properly** - Include user ID in token, set appropriate expiry
5. **Implement role checks** - Use `requireAdmin` middleware for sensitive operations
6. **Sanitize error messages** - Don't expose internal details to client

## 📊 Performance Considerations

Optimize for this system:

1. **Pagination**: Always paginate list endpoints (default 10-20 per page)
2. **Indexing**: Ensure database has indexes on frequently queried columns
3. **Stored Procedures**: Use for complex multi-step calculations (e.g., payroll)
4. **Connection Pooling**: Use `appPool` - don't create new connections per request
5. **Caching**: Cache lookup data (departments, positions) that changes infrequently
6. **Select needed columns only** - Don't `SELECT *` unnecessarily

## 🧪 Testing & Debugging

When helping test features:

1. **Use `http.http` file** - Test endpoints with REST Client extension
2. **Check logs** - Look for stored procedure errors in SQL Server
3. **Verify JWT token** - Ensure token hasn't expired
4. **Trace the flow** - Add logging at each layer (router → controller → service → repository)
5. **Validate database schema** - Confirm tables and stored procedures exist

## 🚀 Implementation Priority

When implementing features, prioritize in this order:

1. **Database Schema** - Define tables, columns, relationships, stored procedures
2. **Repository** - Data access methods
3. **Service** - Business logic, validation
4. **Controller** - Request/response handling
5. **Router** - Endpoint definition
6. **Types** - TypeScript interfaces
7. **Testing** - Verify all operations

## 💡 Tips for Better Development

1. **Reuse existing patterns** - Don't reinvent the wheel; follow established conventions
2. **Keep layers thin** - Each layer should have a single responsibility
3. **Test incrementally** - Build and test one layer at a time
4. **Document complex logic** - Add comments for business calculations
5. **Use descriptive names** - Function/variable names should explain their purpose
6. **Handle all error cases** - Think about what can go wrong
7. **Optimize early** - Consider performance during design, not just optimization
